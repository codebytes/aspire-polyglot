# Django + HTMX polls: Python AppHost

The AppHost itself is written in **Python** (preview). It runs a Django app
**natively** — Aspire creates its virtual environment and installs its
requirements — next to a PostgreSQL container. Voting uses
[HTMX](https://htmx.org/): the server returns HTML fragments, no JavaScript framework.

| Resource | Runs as | Integration |
|----------|---------|-------------|
| `polls` | native Python (`src/.venv`, `run.py` + waitress) | `add_python_app` |
| `polls-venv-creator`, `polls-installer` | create the venv, `pip install -r requirements.txt` | `with_virtual_env`, `with_pip` |
| `pg` / `pollsdb` | PostgreSQL container + database | `add_postgres().add_database()` |

```python
db = builder.add_postgres("pg").add_database("pollsdb")

(
    builder.add_python_app("polls", "./src", "run.py")
    .with_virtual_env(".venv")
    .with_pip()
    .with_reference(db)
    .wait_for(db)
    .with_http_endpoint(env="PORT")
)
```

The Python SDK in `.aspire/modules/` is generated by `aspire restore` from the
packages in `aspire.config.json`; don't edit it by hand.

## Run

Prerequisites: Aspire CLI 13.6.4, .NET 10 SDK, Python 3.12+ with
[uv](https://docs.astral.sh/uv/) (for the AppHost), Docker (for PostgreSQL).

```bash
cd samples/preview/django-htmx-polls
aspire run
```

Open **polls**: three seeded polls are waiting. Vote, then create a poll with
**Add choice** (an HTMX request that returns another input). In the dashboard:

- **Structured logs**: `Vote recorded for 'Python' in poll 1`, `Created poll …`.
- **Traces**: each request with Django and PostgreSQL (psycopg) spans.

> `with_virtual_env(".venv")` keeps the app's environment in `src/.venv`, separate
> from the AppHost's own `.venv`. Call `with_pip()` after it so the installer uses
> the same environment.

## How it is wired

- `with_reference(db)` injects `POLLSDB_URI`, parsed in
  [`settings.py`](src/pollsite/settings.py). Without it Django uses SQLite.
- [`run.py`](src/run.py) starts the OpenTelemetry distro (which reads Aspire's
  `OTEL_*` settings), migrates, seeds sample polls, and serves with waitress.
- Votes use `F('votes') + 1`, so concurrent votes are never lost.

## Tests

```bash
cd src
uv run --with-requirements requirements.txt python manage.py test polls
```

With SQLite the PostgreSQL concurrency test is skipped; the repository smoke suite
runs it against the sample's real database.

## Troubleshooting

`AttributeError: ... has no attribute 'add_postgres'` or `CapabilityError: Unknown
capability` means the Aspire CLI doesn't match `sdk.version` in `aspire.config.json`.
Install CLI 13.6.4, then run `aspire restore --apphost apphost.py`.
